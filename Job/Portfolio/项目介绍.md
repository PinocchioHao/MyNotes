E. Microservices Design and Implementation
E.1 Selected Services
For this project, we selected three key services from the Service Universe platform for microservice implementation:
Service-Municipal-Parking
Handles all parking-related operations, including starting and ending parking sessions, processing payments, and querying history.
This service demonstrates stateful business logic in a microservice context.
Service-Energy-Reporting
Collects and aggregates energy consumption data.
Provides reporting endpoints for analytics and integrates seamlessly with other services through service discovery.
Service-Driver-Booking
Supports driving test appointment booking and management.
Exemplifies a user-facing service with workflow operations and external API exposure.
________________________________________
E.2 Microservices Design
The microservices are designed based on the Spring Boot + Spring Cloud ecosystem, using Eureka for service registration and discovery and Spring Cloud Gateway as a unified API entry point.
Key design principles:
•	Independent Deployment: Each service is packaged as a standalone Spring Boot application, enabling isolated deployment and scaling.
•	Service Discovery: Services register with the Eureka server at startup, allowing dynamic routing and load balancing.
•	API Gateway Routing: External requests are routed through the Gateway, which queries Eureka to forward requests to the appropriate service instance.
•	Decoupled Data Management: Each service manages its own domain data using MyBatis and MySQL, ensuring separation of concerns.
•	Centralized Logging: A custom ProcessLogAspect automatically logs business events in JSON format, stored in a centralized logs/ directory for process mining.
________________________________________
E.3 Implementation Highlights
Service Packaging and Deployment
Each microservice is packaged as an executable Spring Boot JAR.
For deployment, Dockerfiles are provided for containerization.
Services can be started independently or together using Docker Compose, which manages service dependencies, startup order, and networking.
Service Registration and Discovery
On startup, each service registers with Eureka using its application name and port.
The Gateway automatically discovers registered services, enabling dynamic routing without hardcoding service URLs.
Business Logic Implementation
•	Municipal Parking Service:
Exposes endpoints: /startParking, /endParking, /pay, /history.
Uses MyBatis to interact with parking records in MySQL and logs each activity with caseId and timestamp.
•	Energy Reporting Service:
Provides /submitReport and /getSummary endpoints.
Aggregates data for reporting and analytics while automatically logging activities.
•	Driver Booking Service:
Offers /bookTest, /cancelBooking, /getBookingHistory.
Demonstrates workflow operations with structured logging at each step.
 
Logging and Process Mining
A custom ProcessLogger captures structured JSON logs, including activity, resource, caseId, and timestamp.
All logs are centralized in the logs/ directory for subsequent process analysis using tools like Disco or Celonis.
Containerized Microservices
Docker Compose simplifies deployment: services are built into containers, started in the correct order, and connected via a bridge network to simulate a realistic microservice environment.
After building the images, running docker-compose up launches the Eureka server, Gateway, and all microservices in a single command, making the platform fully operational with minimal manual setup.
E.4 Deployment
The deployment of the microservices follows a straightforward containerized approach, ensuring that each service is independently deployable while integrated into a unified system.
 
1.	Build Services
Each microservice, including the API Gateway and Eureka server, is packaged into an executable JAR using Maven.
2.	Upload to AWS Server
The JAR files and Docker configuration files are uploaded to the AWS Linux 2023 instance.
3.	Prepare Docker Environment
Docker and Docker Compose are installed, and a dedicated Docker network is created to allow inter-service communication.
4.	Containerization and Startup
Docker images are built from the provided Dockerfiles. Using Docker Compose, all containers are started together, automatically managing dependencies and network configuration.
5.	Verification and Client Access
After startup, the Eureka server, API Gateway, and microservices are running in their respective containers. Clients can access all services via the Gateway, which handles routing, service discovery, and cross-origin requests.
This deployment approach enables easy scaling, centralized management, and ensures that the microservices are immediately accessible to frontend clients without additional configuration.
