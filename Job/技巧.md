### 1. 沟通习惯：Thinking Out Loud (大声思考)

这是结对编程中最关键的一点。不要闷头写代码，要让面试官实时了解你的意图。

- **先同步思路再动手：** 在写任何逻辑前，先用一两句话描述你的方案：“我打算先处理输入校验，然后用一个 Map 来存储中间结果以优化查询效率，你觉得这个思路可以吗？”
    
- **主动寻求反馈：** 如果你在两个方案间犹豫，直接说出来：“这里可以用简单的 Loop，也可以用 Stream。考虑到代码的可读性，我建议用 Stream，你有什么偏好吗？”
    
- **诚实面对困境：** 卡住时不要沉默。你可以说：“我记得这个库有一个方法可以处理这个逻辑，但具体名称我忘了，我先用伪代码占个位，稍后查一下。”
    

### 2. 代码优雅：Clean Code 的即时体现

面试官非常看重代码的“品味”。

- **见名知意 (Naming)：** 拒绝 `list1`, `temp`, `a`, `b` 这种变量名。哪怕是简单的循环，也要写成 `userList`, `isTransactionValid`。
    
- **保持函数短小：** 如果一个方法超过 15-20 行，考虑将其拆分为私有的辅助方法。这展示了你对 **单一职责原则 (SRP)** 的自觉遵守。
    
- **防御式编程：** 在逻辑开始前，先处理“坏情况”（Guard Clauses）。
    
    Java
    
    ```
    public void processOrder(Order order) {
        if (order == null || order.getItems().isEmpty()) {
            return; // 尽早返回
        }
        // 处理正常逻辑...
    }
    ```
    
- **拒绝硬编码：** 即使是简单的超时时间或状态码，也尽量定义为常量。
    

### 3. 接口 (API) 设计的专业性

如果你在现场写一个 Controller 或 Service 接口，以下细节是“高级”与“初级”的分水岭：

- **输入校验 (Validation)：** 哪怕面试官没要求，也要记得提到或加上基本的校验（如 `@NotBlank`, `@Size`）。
    
- **DTO 的意识：** 不要直接把数据库 Entity 暴露给接口。即使时间紧，也可以提一句：“在实际项目中，我会定义一个 DTO 来解耦。”
    
- **响应一致性：** 考虑异常情况。不要只写成功路径，问一句：“如果数据不存在，我们是返回 404 还是空列表？”
    
- **日志与注释：** 在关键逻辑处随手加一行有意义的注释，并提到“这里我会加一条 SLF4J 日志用于线上监控”。
    

### 4. 算法与逻辑的稳健性

结对编程中的算法通常不难，难在“不出错”。

- **边界检查：** 数组是否为空？索引是否越界？整数是否会溢出？
    
- **清晰胜过巧妙：** 除非性能极其敏感，否则优先选择可读性高的代码，而不是只有你能看懂的位运算或复杂正则。
    
- **DRY 原则 (Don't Repeat Yourself)：** 如果你发现自己写了两次相同的逻辑，立刻停下来进行重构。这种敏锐的察觉力是巨大的加分项。
    

### 5. 测试先行 (TDD 意识)

如果你能主动写单元测试，面试成功率会提升一个量级。

- **先写测试用例：** 在写核心逻辑前，问面试官：“我先写两个简单的测试用例（Happy Path 和 Edge Case）来确保我们的目标一致，可以吗？”
    
- **编写“可测试”的代码：** 尽量少用静态方法或硬编码的 `new` 对象，多用依赖注入，这体现了你对代码可测性的理解。

## 连接词
### 1. 开头：争取思考时间的“万能金句”

当面试官问完一个问题，你不需要立刻开口，可以先用这些话垫一下：

- **"That's a great question."** （这是个好问题。——**最推荐，能换取 2 秒反应时间**）
    
- **"Let me think about that for a second."** （让我想一下。——**非常诚实且自然，澳洲人很吃这一套**）
    
- **"Sure, I can definitely talk about that."** （当然，我很乐意聊聊这个。）
    
- **"In terms of [某项技术/某段经历]..."** （关于……方面……）
    

---

### 2. 衔接与过渡：让逻辑更清晰

当你从总体概括进入到细节时，可以用这些词过渡：

- **"Actually..."** （实际上……——用于引出一个具体的事实）
    
- **"To give you some background..."** （为了给你一些背景信息……——用于开始讲故事或项目）
    
- **"Specifically..."** （具体来说……——用于引出具体的技术细节）
    
- **"In my previous roles..."** （在我之前的职位中……）
    
- **"Speaking of [Topic]..."** （谈到……——用于从一个话题转到另一个话题）
    

---

### 3. 结构化表达：展现逻辑感

澳洲面试官非常喜欢听“第一、第二”，这会让他们觉得你思路清晰：

- **"I’d say there are two/three main parts to this."** （我认为这主要包含两/三个部分。）
    
- **"First of all... and then..."** （首先……然后……）
    
- **"Another thing is..."** （另一件事是……——用于补充一个点）
    

---

### 4. 结尾：礼貌收尾，引导追问

回答完后不要突然沉默，用一句话收尾：

- **"So, that was my experience with [Topic]."** （所以，这就是我在……方面的经验。）
    
- **"Does that answer your question?"** （我回答了您的问题吗？——**非常好的互动方式**）
    
- **"I’m happy to go into more detail if you'd like."** （如果您愿意，我很乐意分享更多细节。）
    

---

### 💡 实战演示：把连接词放入你的脚本

**面试官：** "Tell me about your work experience?"

**你：**

> "**That's a great question.** **To give you some background,** I’ve worked in two main areas.
> 
> **First,** at Huawei, I focused on microservices...
> 
> **And then,** I joined Minsheng Bank. **Actually,** this was a very important transaction system.
> 
> **In terms of the tech stack,** we used Java and Vue. **In my role,** I was responsible for coding and leading a small team.
> 
> **So, that’s a quick overview of my background.** I’m happy to dive deeper if you’re interested in any part of it."

---

### 💡 给你的小贴士：

1. **不要怕停顿**：在澳洲面试中，思考 2-3 秒是很专业的表现。你可以一边点头一边说 "That's a great question..." 来缓解焦虑。
    
2. **避免过多的 "And"**：用 **"Also"** 或 **"In addition"** 来代替重复的 "And"，会让你的英语听起来更有层次感。
    
3. **语气要平和**：这些连接词要说得自然，不要像背书一样。
