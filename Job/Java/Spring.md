## 谈谈对Spring的认识

Spring是一个轻量级的J2EE框架，让人更专注于写业务逻辑，而不用过多关注对象管理等方面，能提升开发效率。它是一个容器框架，用来装Java Bean，同时也是一个中间层框架，起一个连接作用，比如把MyBatis、Struts、Redis等框架连接起来等。

Spring的功能主要是控制反转（IOC）和面向切面（AOP）。

- IOC--松耦合，不需要对象之间进行一个强依赖，而是从IOC容器中取
- 提供了AOP面向切面编程的丰富支持，允许通过分离应用的业务逻辑与系统级服务进行内聚性的开发。（比如日志系统和异常处理等，如果不使用AOP，则打印日志的代码需要分在在业务代码中的各处）
- Spring容器能够管理应用对象（Bean）的配置和生命周期，包括创建、赋值、销毁等。
- 能将简单的组件配置，框架整合成复杂的应用


好处：
1. 轻量
2. 控制反转，松散耦合，减小侵入
3. 提供面向切面编程
4. Spring容器能够装配Bean并控制生命周期
5. MVC框架、事务框架、异常处理

## IOC
Spring容器基本就是指IOC容器，IOC容器负责创建、配置并管理Bean的生命周期。
IOC的实现是基于**工厂模式+反射机制**。（反射创建对象，工厂返回实例）
通过IOC容器避免了手动频繁创建对象，支持使用注解创建对象，将其交给spring容器来管理其生命周期，代码简洁易于维护。

### 作用域

单例（Singleton）和原型（Prototype）。可通过@Scope("prototype")指定。

单例是容器在整个生命周期中只创建一个 Bean 实例，所以这个实例会被复用，适合无状态的、轻量级的对象，比如服务类。

#### Spring Bean的生命周期  -- 偏底层，澳洲一般不问
class-----实例化-----生成对象-----属性填充--（依赖注入）--（处理Aware接口）-初始化(afterPorpertiesSet)-----AOP-----生成代理对象（执行切面逻辑，before方法、当前方法、after方法）-----得到Spring Bean，放入IOC容器单例池 ----- 销毁

如何注入：  
根据类的构造方法（推断构造方法，只有一个构造方法时默认使用该构造方法，有无参方法时默认使用无参，其余则会报错），通过反射，进行实例化，得到对象  
如果有参数，根据byType或者byName去IOC容器中寻找，然后注入

如何匹配切点：  
AOP中把容器中所有的切点找到，再匹配，该bean是否匹配到切点进行AOP操作

#### Spring bean线程安全性

通常是不安全的  
Spring中的Bean默认是单例模式，且框架并没有对bean进行多线程的封装处理。  
最简单的做法就是改变Bean的作用域，将singleton改为prototype，这样每次请求Bean就相当于new Bean()，保证了线程安全。

如果bean中声明了有状态的实例变量或者是类变量，那么可以使用ThreadLocal把变量设置为线程私有；如果bean的实例变量或者是类变量需要在多个线程之间共享，那么就只能使用synchronized、lock、CAS等实现同步方法。

注意：Controller、Service和Dao层本身虽然并不是线程安全的，但是如果只是多线程调用其中的方法，那么每个线程会在自己的**工作内存**中开辟空间复制其中的变量，是安全的。（**局部变量**不考虑线程安全问题）

还有request模式，一般在web应用需要某个请求特定独立的场景下，但是这种场景应用极少，以及使用prototype也能满足



## AOP
面向切面编程，支持程序执行到某一步骤的时候自动进入到特定的逻辑。能将一些公共操作给解耦出来。

用途：
1. Spring自带的如`@RestControllerAdvice`加上`@ExceptionHandler`做统一异常拦截
2. 自定义切面，利用`@Aspectj`注解来指定特定包下特定类或者特定方法执行后执行相应切面逻辑；或者是自定义注解配合`@Aspectj`注解可定点实现该注解处执行切面逻辑，通过`@Before`, `@After`指定切入点，在某个方法前后执行特定的逻辑

### 事务传播特性
比如，A方法调用了B方法（B方法必须使用事务注解），那么B事务可以是一个在A中嵌套的事务，或者B事务不使用事务，又或是使用与A事务相同的事务，这些均可以通过指定事务传播特性来实现。
默认**PROPAGATION_REQUIRED：如果不存在外层事务，就主动创建事务；否则使用外层事务。这是最常见的选择**（Service1开启了事务，Service2可以直接使用，不用配）。
#### 使用场景

- 不重要的项目/普通场景/懒得考虑那么多什么都不填 REQUIRED
- 内层方法与外层方法几乎没有关联，相当于独立执行 REQUIRES_NEW
- 内层方法依赖于外层方法，但是外层方法不希望被内层方法影响(_在插入用户信息后向日志表中插入一条记录_) NESTED
- 内层方法需要和外层方法的操作同步，发生异常时要么都不回滚，要么一起回滚 SUPPORTS
- 内层方法不启用事务，但是可以允许外层方法启用事务 NOT_SUPPORTED
- 内层方法不启用事务，也不允许外层方法启用事务NEVER内层方法必须开启事务，同时在逻辑上依赖于外层方法 MANDATORY

JPA：按照Alibaba开发手册，cascade一定不要用，因为级联对并发操作带来的开销极大，存在外键关系的更新一方另一方会自动更新，此为级联，适用于单机低并发场景；建议采用逻辑外键**Logical Foreign Key**处理，把相关操作放在业务逻辑。



## 实战Tips

### 构造器注入
用了Lombok的@RequiredArgsConstructor就不用到处都写@Autowired了。

这种方式本质上是利用了 Spring 的 **构造器注入（Constructor Injection）** 特性。自 Spring 4.3 版本以后，如果一个类只有一个构造函数，Spring 会自动对该构造函数的参数进行注入，甚至不需要加 `@Autowired` 注解。而 Lombok 的 `@RequiredArgsConstructor` 恰好帮你把这个构造函数写了。 -- 主流推荐写法

直接给出结论：**强烈推荐使用这种写法（Lombok + final 成员变量），彻底抛弃在变量上直接加 `@Autowired` 的做法。**

优点：
1. 构造器注入配合`final`关键字，保证对象不可变，防御性编程
2. 单元测试便利，只需要new一个这个类，mock对象进去就行；不需要引入Mockito大量`@InjectMocks`
3. 循环依赖在启动时就会发现，能迫使开发者在设计和架构阶段就解决
