### Pipeline
1. 准备git仓库
2. 配置流水线
3. 配置Docker和buildspec.yml；
4. push代码后流水线就会自动构建，遇到的问题：docker里面先构建，再运行，不然报错找不到文件
5. 构建完后发给ECR (Elastic Container Registry)

Dockerfile 主要 **描述镜像怎么构建**

buildspec.yml 是 **CodeBuild 构建流程的控制文件**，它负责：
- 登录 ECR
- 指定镜像 tag（如 commit hash）
- 执行 `docker build` 命令时打上 tag
- push 镜像到 ECR
- 生成 `imagedefinitions.json` 给 ECS 部署用



流水线有几种类型，可选推送给ECR或给ECS部署
ECR：只做镜像构建和推送，把构建流水线和部署流水线分开
ECS：服务会自动拉取最新镜像并滚动更新；push代码，自动更新。--始终没创建成功

### AWS App Runner - 傻瓜式建站
1. 配置app runner
2. 从ECR上面拉取资源
3. 配置角色，第一次新建
4. 直接就能跑了！并且跟CodePipeline无缝衔接，实现无脑化push代码就自动热部署
总结：App Runner类似于PaaS，集成了热部署，自动扩容，HTTPS，负载均衡等，好多功能直接拿来用；而ECS这些类似于IaaS，只提供了服务器基础设施；
大型项目需要复杂的网络拓扑（比如多层微服务、复杂安全组）建议搭ECS；而小型项目可以直接App Runner托管
