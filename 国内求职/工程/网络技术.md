### Session vs JWT (分布式鉴权)

这是面试必考的重头戏。单机时代的 Session 已经玩不转了，面试官要听的是你如何解决**分布式跨节点登录**的问题。

| **维度**    | **Session + Cookie**                           | **JWT (JSON Web Token)**                      |
| --------- | ---------------------------------------------- | --------------------------------------------- |
| **存储位置**  | 服务端内存（或集中存入 Redis）                             | 客户端（LocalStorage 或 HttpOnly Cookie）           |
| **状态机制**  | **有状态**。服务端保存着每一个用户的登录信息。                      | **无状态**。服务端不存 Token，靠验证数字签名辨认真伪。              |
| **分布式扩展** | 较差。需依赖 Session 共享机制（如 Spring Session + Redis）。 | **极佳**。任何节点拿到 Token 只要用公钥/秘钥验签即可，天生适合微服务。     |
| **核心痛点**  | 占用服务端内存；跨域限制（Cookie 不易跨域）。                     | **无法主动撤销**（一旦签发，过期前一直有效）；Payload 载荷越大，网络开销越重。 |

如果用户修改了密码，怎么让之前的 JWT 强制失效？
**解法：** JWT 本身做不到，必须借助 Redis。在 Redis 里维护一个黑名单，或者把用户的敏感操作时间戳和 JWT 里的签发时间比对。这就意味着 JWT 又变回了“有状态”，需要向面试官讲透这种**技术折中**。


### TCP vs UDP

| **特性**   | **TCP (传输控制协议)**                     | **UDP (用户数据报协议)**                              |
| -------- | ------------------------------------ | ---------------------------------------------- |
| **连接机制** | 面向连接（三次握手建立，四次挥手断开）                  | 无连接（知道 IP 和端口直接发）                              |
| **可靠性**  | **绝对可靠**。通过确认应答、超时重传、滑动窗口保证数据不丢、不乱序。 | **不可靠**。不管对方收没收到，丢包就丢包。                        |
| **传输效率** | 较慢（报文头部复杂，需要维护连接状态）                  | 极快（报文头部仅 8 字节，没有拥塞控制）                          |
| **应用场景** | HTTP, HTTPS, FTP, 数据库连接等绝大多数场景       | 视频直播、语音通话、在线竞技游戏，以及基于 UDP 封装的新一代 HTTP/3 (QUIC) |




### REST vs RPC

- **REST (Representational State Transfer)：**
    
    - **本质：** 基于 HTTP 协议，使用 JSON 传输，通过 HTTP 动词 (GET, POST, PUT, DELETE) 表达操作语义。
        
    - **优势：** 跨语言极其方便，人类可读性极强，松耦合。
        
    - **场景：** 对外暴露的 Open API，或者前端与后端交互的接口。
        
- **RPC (Remote Procedure Call - 远程过程调用)：**
    
    - **本质：** 像调用本地方法一样调用远程服务。底层通常使用 TCP 或 HTTP/2，数据序列化采用二进制格式（如 Protobuf、Hessian）。代表框架：Dubbo、gRPC。
        
    - **优势：** 需要提供方和调用方共享接口定义（强耦合），带来了**严格的编译期类型检查**，且二进制传输体积小、序列化**速度极快**，性能远超 HTTP/JSON。
        
    - **场景：** 微服务**内部节点之间**的高频、高性能调用。
